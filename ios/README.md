# iOS-приложение (SwiftUI)

Нативное приложение на SwiftUI (iOS 16+), которое ходит в ваш существующий
Go-бэкенд по тем же REST-эндпоинтам, что и веб-версия.

Реализовано в первой версии:
- Регистрация и вход (`/api/v1/auth/register`, `/api/v1/auth/login`),
  токен хранится в Keychain
- Профиль (`/api/v1/users/me`): вуз, курс, статус, баланс, реферальный код,
  выход из аккаунта
- Каталог предложений (`/api/v1/offers`): список с поиском и карточка
  предложения с деталями

## Требования

- macOS с Xcode 15+
- [XcodeGen](https://github.com/yonaskolb/XcodeGen) — генерирует
  `.xcodeproj` из `project.yml`, чтобы не хранить в git бинарный
  Xcode-проект и не редактировать его руками

Установка XcodeGen (один раз):
```bash
brew install xcodegen
```

## Сборка

```bash
cd ios
xcodegen generate
open StudentDiscountApp.xcodeproj
```

Дальше — обычная сборка и запуск в Xcode (⌘R) на симуляторе или устройстве.

## Важно: адрес сервера

По умолчанию приложение обращается к `http://localhost` — это подходит
только для симулятора, если бэкенд поднят на этом же Mac. **Для реального
iPhone** «localhost» указывает на сам телефон, а не на ваш сервер, поэтому
нужно указать настоящий адрес:

- на экране входа есть кнопка **«Адрес сервера»** — впишите туда домен или
  IP вашего сервера (тот же, что открывается в браузере как
  `http://ваш-сервер` или `https://ваш-домен`);
- либо один раз поменяйте `defaultServerURLString` в
  `StudentDiscountApp/Sources/App/AppConfig.swift`.

Если сервер работает по обычному `http://` без TLS-сертификата (как сейчас),
в `project.yml` уже включено `NSAllowsArbitraryLoads: true` (ATS отключён),
иначе iOS просто заблокирует такие запросы. Как появится домен с HTTPS —
эту настройку стоит убрать и сузить до конкретного домена через
`NSExceptionDomains`.

## Структура проекта

```
ios/
  project.yml                  # описание проекта для XcodeGen
  StudentDiscountApp/
    Sources/
      App/                     # точка входа, конфиг сервера
      Models/                  # User, Offer, Auth-модели (под JSON бэкенда)
      Networking/              # APIClient, Keychain, SessionStore
      Views/
        Auth/                  # экраны входа и регистрации
        Profile/                # экран профиля
        Offers/                 # список и детали предложений
        Common/                 # индикаторы загрузки/ошибок
    Resources/
      Assets.xcassets          # иконка приложения, акцентный цвет
```

## Дальнейшие шаги

Каркас сделан так, чтобы легко добавлять остальные разделы по тому же
паттерну (ViewModel + `APIClient.shared.get/post`): заказы (`/api/v1/orders`),
избранное/подписки на компании, уведомления
(`/api/v1/notifications`), друзья. Под push-уведомления вместо SSE
потребуется APNs — это отдельная задача (регистрация device token,
эндпоинт на бэкенде для его сохранения, интеграция с уже существующим
Hub'ом уведомлений).
